# Открытые вопросы

- Решение пользователя: пока работать только с локальными ветками и коммитами. У репозитория игры нет remote; PR и удалённый CI отложены.
- В окружении Python 3.14 и нет глобального `uv`. Этап 0 проверен временной установкой `uv` и PostgreSQL 17. CI использует Python 3.12; проверка именно на 3.12 остаётся за первым запуском CI.
- Для ручной проверки входа через тестового Telegram-бота нужен токен бота и его имя. Автоматические тесты Telegram используют заглушки; реальные учётные данные в репозиторий не добавляются.
- Этап 4: ручные проверки входа по реальной почте (Resend) и через Telegram-бота отложены по решению пользователя. Перенос прогресса при привязке почты проверен автотестом и вручную через `MAIL_BACKEND=console`.
- Этап 4: в контенте пока нет выпадения крышек и босса, поэтому клиент отправляет `picked_caps = 0` и `boss_killed = false`; сервер уже считает и ограничивает оба поля. Подбор крышек и босс добавятся вместе с контентом (этап 6) — уточнить, в каком этапе делать систему Loot.
- Этап 4: хеш контента считается по сырым байтам JSON-файлов (а не по пересериализованному JSON), чтобы клиент и сервер получали одно значение. Сервер читает контент один раз при старте: после правки `content/` перезапустите сервер, иначе забеги получат флаг `content_hash_mismatch`.
- Этап 4: забеги с dev-флагами `?wave=` и `?seed=` ожидаемо получают флаги (`wave_clamped`, `duration_clamped`) — это не ошибка.
- Этап 4: API-тесты по умолчанию идут на SQLite в памяти; с `TEST_DATABASE_URL` — на PostgreSQL через миграции Alembic (down/up и `alembic check`). В CI включён второй вариант.
