# Пустошь — план разработки survivor-like для агента

Nov 11, 2026 · @ты говоришь по русски?

## Обзор

«Пустошь» (рабочее название) — survivor-like с видом сверху в pixel-art, атмосфера ретро-футуристического постапокалипсиса. Выживший выходит из убежища на пустошь, оружие стреляет само, игрок только двигается и выбирает перки. Между забегами он прокачивает убежище за крышки — внутриигровую валюту.

**Платформы:** браузер, Android (Capacitor), позже Telegram Mini App — всё из одной кодовой базы.

**Главное требование к архитектуре:** апгрейды, врагов, оружие и локации можно добавлять без переписывания движка: контент описывается данными, поведение берётся из реестра.

**Состав MVP:**

- 1 локация (Пустошь у убежища), 1 герой, забег 15 минут с боссом в конце
- 4 оружия, 6 пассивных перков, 5 типов врагов, 1 босс
- 8 апгрейдов убежища (мета-прогрессия)
- гостевой вход, вход без пароля по magic-link на почту или через Telegram-бота, удаление аккаунта
- профиль и прогресс хранятся на сервере (PostgreSQL)

**Не входит в MVP:** лидерборды, покупки, Telegram Mini App, мультиплеер, локализация, кроме русского.

**Ограничение по IP:** стилизуемся под Fallout, но не используем его товарные знаки и узнаваемые элементы (Vault Boy, Pip-Boy, Vault-Tec, Nuka-Cola, название Fallout). Все названия придумываем свои.

## Архитектура

Сервер не участвует в игровом цикле: забег целиком считается на клиенте, поэтому в бою нет лагов и можно играть при плохой связи.

&#91;embedded content: архитектура · клиент, сервер, внешние сервисы\]

Клиент ходит на сервер при входе, в начале и конце забега и при покупке апгрейдов. Письма уходят через Resend, вход через Telegram подтверждается вебхуком бота. Каталог `content/` вшивается в клиент и читается сервером, так что цены и награды везде считаются по одним данным.

## Клиент на Phaser

Клиент — набор сцен и независимых систем. Системы читают числа только из контента, в коде констант баланса нет.

**Сцены:**

| Сцена | Назначение |
| --- | --- |
| Boot / Preload | загрузка контента и ассетов, валидация схем, восстановление сессии |
| Auth | «Играть сразу» (гость), вход по почте (ссылка или код), вход через Telegram (кнопка + QR) |
| Hub (Убежище) | апгрейды, выбор героя и локации, статистика, настройки, удаление аккаунта |
| Run | сам забег: мир, герой, враги, снаряды |
| Hud | параллельная сцена поверх Run: HP, опыт, таймер, убийства, джойстик |
| LevelUp | пауза Run + выбор 1 из 3 карточек (новое оружие, уровень оружия, перк) |
| Pause / Result | пауза; итоги забега и награда от сервера |

**Системы в забеге:**

- **Spawner** — идёт по таймлайну волн из локации, спавнит за пределами экрана, держит лимит врагов на экране (стартовая цель — 300).
- **Weapons** — каждое оружие = поведение из реестра + параметры уровня из JSON; стреляет по своему кулдауну.
- **Projectiles** — пулы объектов через Phaser Groups, никаких `new` в игровом цикле.
- **XP** — враги роняют кристаллы опыта, притяжение в радиусе сбора, кривая уровней из контента.
- **Stats** — итоговая характеристика = (база + сумма flat) × (1 + сумма percent). Источники модификаторов: герой, апгрейды убежища, перки забега.
- **Loot** — крышки, аптечки, магнит, сундуки после босса.

**Характеристики героя:** maxHp, armor, regen, moveSpeed, damage, attackSpeed, area, projectileCount, duration, pickupRadius, xpGain, luck, radResist. Список задаётся в одном TS-типе и одной Zod-схеме.

**Управление:** WASD и стрелки на ПК, плавающий виртуальный джойстик на таче (появляется под пальцем).

**Мир:** бесконечная земля через TileSprite, камера следит за героем, декорации (остовы машин, бочки, сухие деревья) генерируются по чанкам из seed забега.

**Производительность:** цель — стабильные 60 FPS при 300 врагах и 500 снарядах в десктопном Chrome. На среднем Android-телефоне замерить на этапе 7. В dev-сборке нужен счётчик FPS и числа сущностей.

**Локальное хранилище:** токены, настройки звука и кэш профиля. Состояние забега никуда не сохраняем: свернул игру — автопауза, закрыл — забег потерян.

## Контент через данные

Новый враг, оружие, апгрейд или локация — это JSON-файл в `content/` плюс спрайт. Код нужен, только когда появляется новое *поведение*.

**Два слоя:**

1. **Поведения (код)** — реестр классов по строковому ключу. Оружие: `projectile`, `spread`, `orbit`, `aura`, `melee_arc`, `chain`, `mine`. Враги: `chaser`, `ranged`, `charger`, `exploder`, `swarm`, `boss_phases`. Каждое поведение объявляет Zod-схему своих параметров.
2. **Контент (данные)** — JSON ссылается на поведение и задаёт числа, спрайты, звуки, теги.

**Типы контента:**

| Каталог | Что описывает |
| --- | --- |
| `heroes/` | базовые статы, стартовое оружие, условие открытия |
| `weapons/` | поведение + таблица уровней 1–8, эволюция (оружие + перк → улучшенная версия) |
| `passives/` | перки забега: модификаторы статов по уровням |
| `enemies/` | поведение ИИ, статы, дроп, теги |
| `locations/` | тайлсет, декор, музыка, таймлайн волн, босс, множитель награды, условие открытия |
| `upgrades/` | апгрейды убежища: стат, тип модификатора, макс. уровень, цена |
| `balance.json` | кривая опыта, формула награды, лимиты для античита |

**Пример врага** (`content/enemies/ghoul.json`):

```json
{
  "id": "ghoul",
  "name": "Гуль",
  "sprite": "enemies/ghoul",
  "ai": { "type": "chaser", "params": { "turnRate": 4 } },
  "stats": { "hp": 12, "speed": 55, "damage": 5, "xp": 1 },
  "drops": [{ "item": "caps", "chance": 0.05, "amount": [1, 3] }],
  "tags": ["mutant"]
}
```

**Пример апгрейда** (`content/upgrades/armor_plates.json`):

```json
{
  "id": "armor_plates",
  "name": "Бронепластины",
  "stat": "armor",
  "mod": "flat",
  "perLevel": 1,
  "maxLevel": 5,
  "cost": { "base": 100, "growth": 1.6 }
}
```

Цена уровня считается одинаково на клиенте и сервере:

```latex
\text{cost}(n) = \operatorname{round}(\text{base} \cdot \text{growth}^{n})
```

**Кто читает контент:** клиент (игра) и сервер (цены апгрейдов, награды, лимиты). Сервер отдаёт бандл и его хеш через `/content`. Клиент берёт серверную версию, а вшитую копию — только если сервер недоступен. Так баланс меняется без пересборки APK. Ассеты нового контента при этом всё равно нужно доставить: новые спрайты = новая версия клиента или загрузка ассетов с CDN.

**Проверка:** `make content-check` валидирует все JSON по схемам, проверяет уникальность `id`, ссылки на поведения, спрайты и врагов в волнах. Запускается в CI.

**Чеклист «добавить врага»:**

1. Положить спрайт в `client/public/assets/enemies/` и пересобрать атлас.
2. Создать `content/enemies/<id>.json` с существующим `ai.type`.
3. Добавить врага в таймлайн волн нужной локации.
4. `make content-check`, запустить забег с dev-флагом `?wave=<n>`, чтобы сразу проверить.

Новая локация и новый апгрейд добавляются так же. Новое поведение = один класс в `behaviors/` + регистрация ключа + схема параметров + тест.

## Pixel-art

Игра рисуется в низком внутреннем разрешении и масштабируется целым коэффициентом, палитра ограничена — так стиль остаётся цельным.

| Параметр | Значение |
| --- | --- |
| Внутреннее разрешение | 480×270 (16:9), Scale.FIT + целочисленный zoom, чёрные поля на нестандартных экранах |
| Настройки Phaser | `pixelArt: true`, `roundPixels: true`, `antialias: false` |
| Тайлы | 16×16 |
| Герой и обычные враги | 16×16 или 24×24, ходьба 4 кадра, удар/смерть 3–4 кадра |
| Боссы | 48×48 и больше |
| Палитра | до 32 цветов: песок, ржавчина, хаки, выцветший теал, радиоактивный зелёный для акцентов |
| UI | стиль старого ЭЛТ-терминала: зелёный монохром, сканлайны, лёгкое свечение |
| Шрифт | пиксельный bitmap-шрифт с кириллицей под OFL или CC0; наличие кириллицы проверить до выбора |
| Эффекты | опциональный CRT-шейдер (сканлайны, виньетка) с выключателем в настройках; вспышка при уроне, тряска камеры |

**Сеттинг и образы:** ретрофутуризм 50-х после атомной войны. Враги: гули, гигантские тараканы и скорпионы, рейдеры, старые роботы-уборщики, супермутант-босс. Оружие: самодельный пистолет, обрез, лазерная винтовка, коктейль Молотова, дрон-спутник (вращается вокруг), радиационная аура.

**Где брать графику:**

1. Этапы 1–4 — заглушки: цветные квадраты и круги, сгенерированные кодом в Preload, с теми же ключами спрайтов, что и финальные.
2. Этап 5 — готовые паки под CC0 или с коммерческой лицензией (itch.io, OpenGameArt) + дорисовка в Aseprite. Лицензия каждого ассета фиксируется в `client/public/assets/CREDITS.md`.
3. Атласы собираются скриптом (free-tex-packer-core или экспорт Aseprite CLI) в JSON Hash для Phaser.

**Звук:** 8-битные SFX (можно сделать в jsfxr), фоновая музыка под CC0/CC-BY, до 3 одновременных экземпляров одного звука.

## Сервер FastAPI

Один сервис FastAPI: аккаунты, вход без паролей (magic-link на почту или через Telegram-бота), письма через Resend API, профиль, забеги и контент. Паролей в системе нет совсем. Все пути с префиксом `/api/v1`.

**Эндпоинты:**

| Метод и путь | Назначение |
| --- | --- |
| `POST /auth/guest` | создать гостя, вернуть токены |
| `POST /auth/email/start` | `{email}` → письмо со ссылкой и 6-значным кодом; ответ всегда 200 |
| `POST /auth/email/verify` | `{token}` из ссылки или `{email, code}` → токены; первый вход = регистрация |
| `POST /auth/telegram/start` | → `{request_id, poll_secret, deep_link}`, где `deep_link` = `https://t.me/<bot>?start=<nonce>` |
| `GET /auth/telegram/poll/{request_id}` | заголовок `X-Poll-Secret` → `pending` / токены / `expired` |
| `POST /telegram/webhook` | вебхук бота, проверка `X-Telegram-Bot-Api-Secret-Token` |
| `POST /auth/refresh` | обмен refresh-токена на новую пару (ротация) |
| `POST /auth/logout` | отозвать refresh-токен |
| `DELETE /account` | удаление аккаунта (требование Google Play) |
| `GET /profile` | профиль: крышки, уровни апгрейдов, открытия, статистика, привязанные способы входа, `version` |
| `POST /upgrades/{id}/buy` | купить следующий уровень; тело `{expected_version}`, 409 при конфликте |
| `POST /runs/start` | локация + герой → `run_id`, `seed`, `content_hash` |
| `POST /runs/{id}/finish` | сводка забега → награда, посчитанная сервером, и новый профиль |
| `GET /content` | бандл контента + ETag по хешу |
| `GET /health` | проверка живости и связи с базой |

Если `email/start` или `telegram/start` вызван с access-токеном, способ входа привязывается к текущему аккаунту. Так гость становится полноценным игроком, а к почте можно добавить Telegram и наоборот. Если эта почта или Telegram уже привязаны к другому аккаунту, игрок входит в него, а гостевой прогресс не переносится; клиент предупреждает об этом заранее.

**Вход по почте (magic-link):**

1. `email/start` приводит email к нижнему регистру и создаёт запись в `login_tokens`: случайный токен 32 байта + 6-значный код, в базе только хеши, срок 15 минут, одноразово, не более 5 попыток ввода кода.
2. Письмо уходит через Resend API: `POST https://api.resend.com/emails`, заголовок `Authorization: Bearer $RESEND_API_KEY`, поля `from`, `to`, `subject`, `html`, `text`. Вызов через `httpx.AsyncClient` с тайм-аутом 10 секунд и повторами при 429/5xx. Заголовок `Idempotency-Key` = id записи `login_tokens`, чтобы повтор не слал второе письмо. Отправка в `BackgroundTasks`, ошибки логируются. Шаблоны писем — Jinja2.
3. Ссылка в письме: `https://<домен>/login?token=…`. В браузере эта страница обменивает токен на сессию. На Android через Android App Links (`/.well-known/assetlinks.json`) ссылка открывает приложение, её ловит обработчик `appUrlOpen` из @capacitor/app.
4. Код из письма — запасной путь, когда письмо открыто на другом устройстве: его вводят прямо в игре.
5. В Resend нужно подтвердить домен-отправитель: добавить DNS-записи SPF и DKIM из их панели, плюс DMARC. Лимиты отправки зависят от тарифа — сверить с ожидаемым числом входов.
6. В dev `MAIL_BACKEND=console`: письмо со ссылкой и кодом печатается в лог сервера. `MAIL_BACKEND=resend` — на стейджинге и в проде.

**Вход через Telegram-бота:**

1. Клиент вызывает `telegram/start`; сервер создаёт запрос входа с `nonce` и `poll_secret` (в базе хеши, срок 5 минут) и отдаёт deep link.
2. Клиент открывает deep link: на Android — приложение Telegram, на ПК — Telegram Desktop или веб-версию. Параллельно на экране игры показывается QR-код с той же ссылкой, чтобы войти с телефона.
3. Бот получает `/start <nonce>` и отвечает сообщением с кнопкой «Войти в игру». Нажатие (callback) привязывает `telegram_user_id` к запросу и меняет статус на `confirmed`. Кнопка нужна, чтобы пересланная чужая ссылка не срабатывала молча.
4. Клиент опрашивает `telegram/poll` раз в 2 секунды с `poll_secret` и после подтверждения получает токены; запрос сразу гасится.
5. Бот на aiogram 3 живёт в том же процессе FastAPI и работает через вебхук. В dev — отдельный тестовый бот в режиме polling, чтобы не нужен был публичный адрес.
6. На будущее: в Telegram Mini App вход происходит без бота-посредника — сервер проверяет подпись `initData` и находит тот же аккаунт по `telegram_user_id`.

**Токены:**

- access — JWT на 15 минут, в заголовке `Authorization: Bearer`; cookie не используем (Capacitor и другой origin).
- refresh — случайные 32 байта, в базе только хеш SHA-256, срок 30 дней, ротация при каждом обмене.
- Повторное использование уже обменянного refresh = признак кражи → отзываем всю цепочку.
- Гость получает те же токены; потерял их до привязки почты или Telegram — потерял прогресс. Клиент предлагает привязать вход после третьего забега.

**Защита эндпоинтов:**

- Лимиты: `email/start` — 1 в минуту и 5 в сутки на email, 20 в час с IP; `telegram/start` — 10 в минуту с IP; `telegram/poll` — 1 запрос в секунду на запрос входа. Реализовать в nginx (`limit_req`) + счётчики в базе по email.
- Ответы не выдают, существует ли аккаунт с такой почтой.
- CORS: домен игры, `https://localhost` (Capacitor Android), `capacitor://localhost` (на будущее для iOS), dev-адрес Vite.
- Ошибки в едином формате `{code, message}`, коды ошибок перечислены в OpenAPI.

## База PostgreSQL

Семь таблиц, паролей нет: способы входа (почта, Telegram) хранятся отдельно от пользователя, их может быть несколько у одного аккаунта. Валюта и версия профиля вынесены в обычные колонки, всё растущее (уровни апгрейдов, открытия, статистика) лежит в JSONB с номером схемы.

| Таблица | Ключевые колонки |
| --- | --- |
| `users` | `id` uuid PK, `is_guest` bool, `display_name` NULL, `created_at`, `last_seen_at` |
| `auth_identities` | `id`, `user_id` FK, `provider` (email / telegram), `subject` (email в нижнем регистре или Telegram user id), `verified_at`, UNIQUE (`provider`, `subject`) |
| `login_tokens` | `id` uuid, `email`, `user_id` NULL (если привязка к текущему аккаунту), `token_hash` UNIQUE, `code_hash`, `attempts` int, `expires_at`, `used_at` NULL |
| `telegram_login_requests` | `id` uuid, `nonce_hash` UNIQUE, `poll_secret_hash`, `user_id` NULL (привязка), `telegram_user_id` NULL, `status` (pending / confirmed / consumed / expired), `expires_at` |
| `refresh_tokens` | `id` uuid, `user_id` FK, `token_hash` UNIQUE, `family_id` uuid, `expires_at`, `revoked_at` NULL, `replaced_by` NULL, `user_agent` |
| `profiles` | `user_id` PK FK, `version` int, `schema_version` int, `caps` bigint, `best_time_s` int, `data` jsonb, `updated_at` |
| `runs` | `id` uuid, `user_id` FK, `location_id`, `hero_id`, `seed` bigint, `content_hash`, `status` (started / finished / rejected), `started_at`, `finished_at`, `summary` jsonb, `reward_caps` int, `flags` text\[\] |

**Решения:**

- Все FK на `users` с `ON DELETE CASCADE`, чтобы `DELETE /account` удалял данные одним запросом.
- Индексы: `runs (user_id, started_at DESC)`, частичный `runs (status) WHERE status = 'started'` для чистки брошенных забегов, `refresh_tokens (user_id)`.
- Задача по расписанию (systemd timer) удаляет гостей без активности 90 дней и просроченные `login_tokens` и `telegram_login_requests` старше суток.
- Миграции только Alembic; автогенерацию всегда просматривать руками.
- Миграция сейвов: функции `migrate_v1_to_v2(data)` в `services/profile_migrations.py`, применяются лениво при чтении профиля.
- **PgBouncer:** в режиме transaction pooling у asyncpg нужно отключить кэш prepared statements (`statement_cache_size=0` и `prepared_statement_cache_size=0` в SQLAlchemy), иначе посыпятся ошибки «prepared statement does not exist». Alembic гонять напрямую в Postgres, минуя PgBouncer.

## Защита от читов

Сервер — единственный источник правды для крышек и уровней апгрейдов. Клиент только просит и показывает. Цель MVP — не дать накрутить валюту одним запросом, а не полная защита.

1. **Забег начинается на сервере.** `runs/start` фиксирует `started_at` по часам сервера и выдаёт `run_id`. Одновременно один активный забег на пользователя, брошенный закрывается через 1 час.
2. **Засчитывается один раз.** Повторный `finish` с тем же `run_id` возвращает уже начисленную награду (идемпотентность на случай обрыва связи).
3. **Награду считает сервер.** Клиент присылает сводку: время, убийства по типам, достигнутая волна, босс убит или нет, подобранные крышки. Сервер считает награду по формуле из `balance.json`.
4. **Проверка правдоподобия:** длительность не больше серверного `finished_at − started_at` + 30 секунд; убийств и крышек не больше лимита в секунду из контента; `content_hash` совпадает. Нарушение → награда урезается до лимита, забег помечается в `flags`. Автоматически не баним.
5. **Покупки в транзакции.** `UPDATE profiles SET caps = caps - :cost, version = version + 1 … WHERE user_id = :id AND version = :expected AND caps >= :cost`. Ноль строк → 409, клиент перечитывает профиль.
6. **Потом, для лидербордов:** детерминированная симуляция от `seed` + лог ввода и выборов перков, чтобы проиграть забег на сервере. Для этого уже сейчас вся случайность в забеге должна идти через сидируемый генератор, а не `Math.random()`.

## Android и деплой

Android-сборка — та же веб-сборка в Capacitor; сервер разворачивается как обычный Python-сервис за nginx.

**Android (Capacitor):**

- `capacitor.config.ts`: `appId`, `webDir: 'dist'`, `server.androidScheme: 'https'`.
- Сборка: `npm run build && npx cap sync android && cd android && ./gradlew bundleRelease`. Keystore и пароли — вне репозитория.
- Альбомная ориентация, полноэкранный immersive-режим, учёт выреза камеры (safe area).
- Кнопка «назад» в забеге = пауза, в Hub = выход с подтверждением. Уход в фон = автопауза и выключение звука.
- Magic-link из письма открывает приложение через Android App Links (assetlinks.json на домене игры, подпись ключом релиза). Токены в @capacitor/preferences; в браузере — localStorage через тот же интерфейс `TokenStore`.
- Для Google Play: удаление аккаунта в приложении и веб-страница `/delete-account`, политика конфиденциальности по ссылке, форма Data safety, target SDK по текущим требованиям Play (проверить перед релизом).

**Сервер:**

- uvicorn (или gunicorn с uvicorn-воркерами) под systemd, слушает unix-сокет или 127.0.0.1.
- nginx: TLS от Let's Encrypt, `/api/` → сервис, остальное — статика клиента; файлы с хешем в имени — `Cache-Control: immutable` на год, `index.html` — без кэша.
- PostgreSQL через PgBouncer, бэкапы `pg_dump` раз в сутки + хранение на другом хосте.
- Конфигурация через переменные окружения (pydantic-settings): `DATABASE_URL`, `JWT_SECRET`, `RESEND_API_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET`, `PUBLIC_URL`, `CORS_ORIGINS`.
- CI на GitHub Actions: ruff, mypy, pytest с PostgreSQL, установленным прямо на раннере, сборка клиента, `content-check`.

**Персональные данные:** если среди игроков будут граждане РФ, то по 152-ФЗ их email нужно хранить на сервере в России — уточнить с юристом до запуска. Отдельно учесть, что отправка адресов в Resend (сервис в США) может считаться трансграничной передачей персональных данных.

## Этапы работ

Девять этапов (0–8) по порядку. Играбельный забег появляется уже на этапе 1, аккаунты — на этапе 3. Следующий этап не начинается, пока не выполнены критерии готовности предыдущего.

0. **Каркас.** Монорепозиторий по структуре выше, Vite + Phaser с пустой сценой, FastAPI с `/health`, Alembic, Makefile, CI, `CLAUDE.md`.
   - Готово: `make dev` поднимает клиент и сервер локально без Docker (PostgreSQL уже установлен), CI зелёный, README описывает запуск с нуля.
1. **Ядро забега на заглушках.** Движение, камера, бесконечная земля, враг `chaser`, автооружие `projectile`, опыт, выбор 1 из 3, смерть, таймер, Hud, виртуальный джойстик.
   - Готово: забег играется от старта до смерти, 60 FPS при 300 врагах в десктопном Chrome, вся случайность через сидируемый генератор.
2. **Контент-система.** Zod-схемы, реестры поведений, перенос всего из этапа 1 в JSON, `make content-check`, dev-флаги `?wave=` и `?seed=`.
   - Готово: второй враг и второе оружие добавлены только JSON-файлами, в коде нет чисел баланса.
3. **Аккаунты.** Гость, magic-link по почте (ссылка + код) через Resend, вход через Telegram-бота, привязка способов входа, refresh-ротация, удаление аккаунта, сцена Auth.
   - Готово: тесты на каждый эндпоинт зелёные (Resend и Telegram замоканы), в dev вход по ссылке из лога и через тестового бота работает руками, гость после привязки сохраняет прогресс.
4. **Профиль и мета.** `profile`, `runs/start` и `finish` с серверным расчётом награды, покупка апгрейдов, сцена Hub.
   - Готово: прогресс переживает вход с другого устройства, поддельная сводка с 10 000 убийств за минуту получает урезанную награду и флаг, двойная покупка с одной версией → 409.
5. **Pixel-art и звук.** Замена заглушек, UI в стиле терминала, анимации, SFX, музыка, `CREDITS.md`.
   - Готово: в игре не осталось заглушек, у каждого ассета записана лицензия.
6. **Контент MVP и баланс.** 4 оружия, 6 перков, 5 врагов, босс, 8 апгрейдов, 15-минутный таймлайн волн.
   - Готово: первый забег без апгрейдов длится 4–8 минут, босс проходим примерно после 10 забегов.
7. **Android.** Capacitor, App Links для magic-link, открытие Telegram по deep link, релизная подпись, замер FPS на реальном телефоне.
   - Готово: AAB собирается одной командой, оба способа входа работают на телефоне, стабильные FPS на среднем устройстве.
8. **Деплой и бета.** systemd, nginx, TLS, бэкапы, вебхук бота, домен в Resend, закрытое тестирование в Google Play.
   - Готово: игра доступна по домену и в закрытом тесте Play, письма доходят во входящие, а не в спам.

## Правила для агента

Эти правила копируются в `CLAUDE.md` в корне репозитория на этапе 0.

1. Работать строго по этапам: один этап = одна ветка и один PR. Не тащить фичи из следующих этапов.
2. В конце этапа проверить каждый пункт «Готово», обновить README и написать, как проверить результат руками.
3. В коде нет чисел баланса: урон, скорости, цены, награды — только в `content/`.
4. Новый контент — через JSON и существующие поведения. Новое поведение — класс в `behaviors/`, схема параметров и тест.
5. TypeScript в strict-режиме без `any`; Python с типами, ruff и mypy без ошибок.
6. На каждый эндпоинт — тесты на успех и ошибки; на формулы цен и наград — юнит-тесты на клиенте и сервере с одинаковыми входными данными. Resend и Telegram в тестах всегда замоканы.
7. Схема базы меняется только миграциями Alembic; автогенерацию проверять глазами.
8. Секреты (ключ Resend, токен бота, JWT\_SECRET, keystore) — только в `.env` и не в репозитории; в репозитории лежит `.env.example`.
9. Не добавлять Docker, пароли и SMTP — это осознанно исключено.
10. Не использовать товарные знаки и узнаваемые элементы Fallout в названиях, текстах и графике.
11. Новая зависимость — только с объяснением в PR зачем она нужна.
12. Неясно, как поступить — записать вопрос в `docs/OPEN_QUESTIONS.md`, выбрать самый простой обратимый вариант и продолжать.
