# Правила разработки «Пустоши»

1. Работать по этапам из `docs/PLAN.md`: один этап — одна локальная ветка и коммит. По решению пользователя пока не создавать PR и не отправлять коммиты в remote. Не добавлять возможности будущих этапов раньше времени.
2. Перед завершением этапа проверить каждый критерий «Готово», обновить README и описать ручную проверку.
3. Числа баланса (урон, скорости, цены, награды) хранить только в `content/`.
4. Контент добавлять через JSON и существующие поведения; для нового поведения нужны класс, схема параметров и тест.
5. TypeScript — strict и без `any`; Python — с типами, ruff и mypy без ошибок.
6. На каждый API endpoint нужны тесты на успех и ошибки. Формулы цен и наград проверять одинаковыми входами на клиенте и сервере; Resend и Telegram в тестах мокать.
7. Схему БД менять только через проверенные миграции Alembic.
8. Секреты хранить в `.env`, а не в репозитории; образец — `.env.example`.
9. Не добавлять Docker, пароли и SMTP.
10. Не использовать товарные знаки и узнаваемые элементы Fallout.
11. Новую зависимость объяснять в PR.
12. Неясный вопрос записывать в `docs/OPEN_QUESTIONS.md`, выбирать простой обратимый вариант и продолжать.
