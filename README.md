# Пустошь

Survivor-like про выжившего у убежища. Сейчас реализованы **этапы 0–4: каркас, играбельный забег, каталог контента, аккаунты, профиль и мета-прогрессия**. [Полный план](docs/PLAN.md).

## Требования

- Node.js 22.12+ и npm
- Python 3.12 и [uv](https://docs.astral.sh/uv/)
- PostgreSQL 16+ (локально, без Docker)

## Первый запуск

```bash
createdb wasteland
cp .env.example .env
# В .env задайте JWT_SECRET случайной строкой длиной не менее 32 символов:
# openssl rand -hex 32
make install
make migrate
make dev
```

Если PostgreSQL использует отдельного пользователя, измените `DATABASE_URL` в `.env`. URL должен начинаться с `postgresql+asyncpg://`. `make dev` запускает сервер на `http://localhost:8000` и клиент на `http://localhost:5173`. Для проверки сервера откройте `http://localhost:8000/api/v1/health`; игра доступна в браузере на порту 5173.

Для локального входа по почте оставьте `MAIL_BACKEND=console`: ссылка и код выводятся в лог сервера. Для реальной отправки задайте `MAIL_BACKEND=resend`, `RESEND_API_KEY` и `MAIL_FROM` с подтверждённым доменом. Для входа через Telegram задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`; в отдельном терминале запустите `make bot-poll`. Вебхук для развернутого сервера дополнительно требует `TELEGRAM_WEBHOOK_SECRET`.

## Команды

| Команда | Назначение |
| --- | --- |
| `make install` | Установить зависимости клиента и сервера |
| `make dev` | Запустить оба dev-сервера |
| `make bot-poll` | Запустить тестового Telegram-бота в режиме polling |
| `make migrate` | Применить миграции Alembic |
| `make test` | Запустить проверки Python, тесты и проверки клиента |
| `TEST_DATABASE_URL=postgresql+asyncpg:///wasteland_test make test` | То же, но тесты API идут на PostgreSQL после миграций Alembic (база очищается!) |
| `make content-check` | Проверить схемы JSON, реестры поведений и ссылки между файлами |

Числа забега лежат в `content/`: `balance.json` задаёт общие лимиты и кривую опыта, а каталоги `heroes/`, `weapons/`, `passives/`, `enemies/` и `locations/` — игровой контент. Клиент проверяет JSON через Zod при загрузке. Для нового врага достаточно JSON в `content/enemies/` и ссылки в волне локации; для нового оружия — JSON в `content/weapons/`. Заглушки спрайтов генерируются по ключам из данных. Новое поведение требует класса и регистрации в `client/src/behaviors/`. Настоящие ассеты придут на этапе 5.

Улучшения убежища лежат в `content/upgrades/` (характеристика, `flat`/`percent`, прибавка за уровень, максимум, цена `base × growth^уровень`). Формула награды и лимиты правдоподобия — в разделе `reward` файла `balance.json`. Цены, награды и хеш контента одинаково считаются на клиенте (`client/src/economy.ts`, `client/src/content/hash.ts`) и сервере (`server/app/services/economy.py`, `content.py`); общие примеры с ожидаемыми ответами лежат в `testdata/economy_vectors.json` и проверяются тестами с обеих сторон. При изменении формулы обновите обе реализации и этот файл.

Сервер — единственный источник правды для крышек: `POST /runs/start` выдаёт `run_id` и seed, `POST /runs/{id}/finish` сам считает награду по сводке, урезает неправдоподобные значения (время по серверным часам + запас, убийства и крышки в секунду, волна, босс, хеш контента) и записывает флаги. Повторный `finish` возвращает уже начисленную награду. Новый `start` закрывает незавершённый забег с флагом `abandoned` (или `expired` старше часа). Покупка улучшения требует `expected_version`; при несовпадении — 409, клиент перечитывает профиль.

Pixel-art и Android относятся к следующим этапам.

## Проверка вручную

1. Запустите `make dev`, откройте клиент и войдите как гость, по почте или через Telegram. Откроется убежище: крышки, лучшее время, число забегов и список улучшений с ценами. Нажмите «Выйти из убежища» (или пробел). Герой двигается через WASD/стрелки, на таче — плавающим джойстиком слева. Оружие автоматически стреляет в ближайшего врага.
2. Соберите кристаллы опыта, выберите улучшение кликом или клавишами 1–3. Нажмите P для паузы. После смерти откроется итоговый экран: сначала оценка награды, затем награда от сервера и новый баланс. «В убежище» возвращает в хаб. Если сервер недоступен, появится «Повторить»; после запуска сервера повтор засчитает тот же забег.
3. В убежище купите улучшение (первый забег даёт около 10–15 крышек, «Бронепластины» стоят 30). Баланс уменьшится на цену, уровень и следующая цена обновятся. В следующем забеге «Полевая подготовка» увеличивает максимум здоровья на HUD. Чтобы проверить 409, в другой вкладке купите улучшение и затем нажмите «Купить» в старой: появится «Профиль изменился», профиль перечитается.
4. Прогресс на другом устройстве: в убежище гостя привяжите почту, откройте игру в другом браузере, войдите по коду из лога сервера — крышки и улучшения те же.
5. Поддельная сводка: возьмите `access_token` из `localStorage['wasteland.auth.v1']`, вызовите `POST /api/v1/runs/start`, затем сразу `POST /api/v1/runs/{run_id}/finish` с `{"content_hash": "...", "duration_seconds": 60, "kills_by_type": {"ghoul": 10000}, "wave_reached": 3, "boss_killed": true, "picked_caps": 10000}`: в ответе урезанная награда и флаги `duration_clamped`, `kills_clamped`, `caps_clamped` и т. д.
6. Откройте `/api/v1/health`: при доступной БД ответ `{"status":"ok","database":"ok"}`. Если БД недоступна, сервер вернёт HTTP 503 в формате `{ "code": ..., "message": ... }`.
7. На экране убежища можно привязать почту/Telegram к гостю и удалить аккаунт вместе с данными. Гостю после третьего забега показывается предложение привязать вход. Выполните `make test` и `make content-check`.

В dev-режиме `?autostart` сразу начинает забег из убежища, `?seed=42` заменяет серверный seed, `?wave=1` запускает вторую волну (нумерация с нуля). Во второй волне появляются два типа врагов. На повышении уровня обрез появляется среди карточек как новое оружие. HUD показывает FPS, число врагов и снарядов. Контрольный замер в headless Chromium после перехода на контент: 300 врагов и 500 снарядов, 120 кадров за 2 секунды.
