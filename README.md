# Пустошь

Survivor-like про выжившего у убежища. Сейчас реализованы **этапы 0–6: каркас, играбельный забег, каталог контента, аккаунты, профиль и мета-прогрессия, pixel-art и звук, контент MVP**. [Полный план](docs/PLAN.md).

## Требования

- Node.js 22.12+ и npm
- Python 3.12 и [uv](https://docs.astral.sh/uv/)
- PostgreSQL 16+ (локально, без Docker)

## Первый запуск

```bash
createdb wasteland
cp .env.example .env
# В .env задайте JWT_SECRET случайной строкой длиной не менее 32 символов:
# openssl rand -hex 32
make install
make migrate
make dev
```

Если PostgreSQL использует отдельного пользователя, измените `DATABASE_URL` в `.env`. URL должен начинаться с `postgresql+asyncpg://`. `make dev` запускает сервер на `http://localhost:8000` и клиент на `http://localhost:5173`. Для проверки сервера откройте `http://localhost:8000/api/v1/health`; игра доступна в браузере на порту 5173.

Для локального входа по почте оставьте `MAIL_BACKEND=console`: ссылка и код выводятся в лог сервера. Для реальной отправки задайте `MAIL_BACKEND=resend`, `RESEND_API_KEY` и `MAIL_FROM` с подтверждённым доменом. Для входа через Telegram задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`; в отдельном терминале запустите `make bot-poll`. Вебхук для развернутого сервера дополнительно требует `TELEGRAM_WEBHOOK_SECRET`.

## Команды

| Команда | Назначение |
| --- | --- |
| `make install` | Установить зависимости клиента и сервера |
| `make dev` | Запустить оба dev-сервера |
| `make bot-poll` | Запустить тестового Telegram-бота в режиме polling |
| `make migrate` | Применить миграции Alembic |
| `make test` | Запустить проверки Python, тесты и проверки клиента |
| `TEST_DATABASE_URL=postgresql+asyncpg:///wasteland_test make test` | То же, но тесты API идут на PostgreSQL после миграций Alembic (база очищается!) |
| `make content-check` | Проверить схемы JSON, реестры поведений, ссылки между файлами, наличие спрайтов/звуков и записей в `CREDITS.md` |
| `make assets` | Пересобрать спрайты, атлас, звуки и музыку (нужен `ffmpeg`) |

Числа забега лежат в `content/`: `balance.json` задаёт общие лимиты, кривую опыта и формулу награды, а каталоги `heroes/`, `weapons/`, `passives/`, `enemies/`, `pickups/`, `upgrades/` и `locations/` — игровой контент. Клиент проверяет JSON через Zod при загрузке. Для нового врага достаточно JSON в `content/enemies/` и ссылки в волне локации; для нового оружия — JSON в `content/weapons/`. Новое поведение требует класса и регистрации в `client/src/behaviors/`.

Улучшения убежища лежат в `content/upgrades/` (характеристика, `flat`/`percent`, прибавка за уровень, максимум, цена `base × growth^уровень`). Формула награды и лимиты правдоподобия — в разделе `reward` файла `balance.json`. Цены, награды и хеш контента одинаково считаются на клиенте (`client/src/economy.ts`, `client/src/content/hash.ts`) и сервере (`server/app/services/economy.py`, `content.py`); общие примеры с ожидаемыми ответами лежат в `testdata/economy_vectors.json` и проверяются тестами с обеих сторон. При изменении формулы обновите обе реализации и этот файл.

Сервер — единственный источник правды для крышек: `POST /runs/start` выдаёт `run_id` и seed, `POST /runs/{id}/finish` сам считает награду по сводке, урезает неправдоподобные значения (время по серверным часам + запас, убийства и крышки в секунду, волна, босс, хеш контента) и записывает флаги. Повторный `finish` возвращает уже начисленную награду. Новый `start` закрывает незавершённый забег с флагом `abandoned` (или `expired` старше часа). Покупка улучшения требует `expected_version`; при несовпадении — 409, клиент перечитывает профиль.

## Контент забега

| Что | Сейчас | Поведения (код) |
| --- | --- | --- |
| Оружие | самодельный пистолет, обрез, лазерная винтовка (пробивает врагов), дрон-спутник, радиационное поле, бутылка с горючим | `projectile`, `orbit`, `aura`, `zone` |
| Эволюции | гвоздемёт (пистолет + пружинный спуск), ломовая пушка (обрез + заряженные патроны), призменный излучатель (лазер + сдвоенный магазин), рой дронов (дрон + магнит из лома), сердце реактора (радиополе + радиогубка), напалм (бутылка + широкий раструб) | те же поведения, `evolved: true` |
| Перки | 8: урон, скорость, скорость атак, область, +снаряд, регенерация, радиус сбора, удача | модификаторы статов |
| Враги | бродяга, таракан, скорпион (рывок), рейдер (стреляет), робот-уборщик (взрывается) | `chaser`, `charger`, `ranged`, `exploder` |
| Мини-боссы | громила (4:30 и 11:30), боевой автомат (8:30); из них выпадает сундук | те же поведения, `role: "elite"` |
| Босс | Король свалки в 13:00 (обычные волны почти стихают): три фазы по здоровью, призывает подмогу; убийство = победа и бонус `bossBonus` | `boss_phases` |
| Бонусы | крышки из врагов, аптечка, магнит, импульсная граната, заначка, сундук | `caps`, `heal`, `magnet`, `blast`, `chest` |
| Апгрейды убежища | 8: броня, здоровье, скорость, урон, регенерация, радиус сбора, удача, опыт | модификаторы статов |

**Эволюция оружия:** когда оружие достигло 8-го уровня, а парный перк взят хотя бы на 1-й уровень, на повышении уровня первой карточкой (золотая рамка, «ЭВОЛЮЦИЯ») предлагается улучшенная версия; сундук выдаёт готовую эволюцию в первую очередь. Эволюция заменяет базовое оружие. Пара задаётся в JSON базового оружия (`"evolution": {"passive": "...", "into": "..."}`), у эволюции один уровень и `"evolved": true`; она не выпадает как новое оружие. `make content-check` проверяет, что перк и цель существуют и у каждой эволюции ровно один источник.

**Сундук** (после мини-босса) сразу улучшает 1–3 предмета (сначала готовую эволюцию, затем уже взятые, по возможности разные; удача повышает число) и даёт крышки. **Ландшафт** генерируется кусками 256×256 из seed забега: асфальт, воронки, светящиеся лужи, дюны, остовы машин, бочки, деревья, кости, шины. **Ящики** на карте разбиваются выстрелом или касанием и дают бонус. Волны, время появления мини-боссов и босса, декор и содержимое ящиков задаются в `content/locations/`.

Поведения работают через маленькие интерфейсы (`client/src/behaviors/types.ts`), а не через объекты Phaser, поэтому у каждого есть юнит-тест (`behaviors.test.ts`). Новое поведение: класс + Zod-схема параметров + регистрация в `behaviors/registry.ts` + тест; поля уровня оружия, которые ему нужны, перечисляются в `requiredLevelFields` и проверяются `make content-check`.

## Графика и звук

Все спрайты, звуки и музыка — собственные (CC0) и собираются скриптом `tools/assets/build_assets.py` (`make assets`) из исходников в репозитории: пиксельные карты в `tools/assets/art.py`, синтез звука и трекер музыки в `tools/assets/audio.py`. Результат лежит в `client/public/assets/` и коммитится, так что для игры и CI скрипт не нужен; повторная сборка даёт те же байты. Лицензии — в `client/public/assets/CREDITS.md`.

- **Атлас** `atlas/sprites.png` + JSON Hash. Кадр `<ключ>` — статичный кадр спрайта из контента (`heroes/wanderer`), кадры `<ключ>/<анимация>_<n>` превращаются в анимации автоматически (`walk`, `death`, `idle`, `burst`).
- **Новый враг со спрайтом:** нарисуйте карту в `art.py` (16×16, символы палитры), добавьте его в `sprite_frames()` (для ходячих — `humanoid(...)`, кадры смерти генерируются), выполните `make assets` и `make content-check`.
- **Звуки:** оружие ссылается на звук выстрела (`fireSound: "sfx/…"`), локация — на музыку (`music: "music/…"`), перки — на иконку (`sprite`). Одновременно звучит не больше трёх экземпляров одного звука.
- **Интерфейс:** стиль ЭЛТ-терминала, шрифт Press Start 2P с кириллицей (OFL, npm-пакет `@fontsource/press-start-2p` — единственная новая зависимость, нужна, чтобы шрифт с кириллицей собирался Vite вместе с клиентом и работал офлайн и в Capacitor). Размеры шрифта кратны 8 px, чтобы пиксели оставались чёткими.
- **Настройки** в убежище: музыка, звуки и ЭЛТ-эффект (сканлайны и виньетка поверх экрана); хранятся в `localStorage`.

## Android

Android-сборка — та же веб-сборка в Capacitor 8 (`client/android`, `client/capacitor.config.ts`). Новые зависимости: `@capacitor/core`, `@capacitor/android`, `@capacitor/cli` (сама обёртка), `@capacitor/preferences` (токены на устройстве), `@capacitor/app` (кнопка «назад», сворачивание, ссылки входа), `@capacitor/app-launcher` (открыть бота в приложении Telegram).

- **Нужно:** JDK 21 (`JAVA_HOME`) и Android SDK с платформой 36 (`ANDROID_HOME`), лицензию SDK принимает пользователь (`sdkmanager --licenses`).
- **Телефон для проверки:** `make dev`, телефон по USB с отладкой, затем `make android-debug` — сборка с API `http://localhost:8000`, `adb reverse` пробрасывает порт на компьютер, APK ставится и запускается. HTTP разрешён только в debug и только для localhost.
- **Релиз одной командой:** `ANDROID_PUBLIC_URL=https://<домен> WASTELAND_KEYSTORE=<путь> WASTELAND_KEYSTORE_PASSWORD=… WASTELAND_KEY_ALIAS=… WASTELAND_KEY_PASSWORD=… make android-aab` → `client/android/app/build/outputs/bundle/release/app-release.aab`. Ключ и пароли — вне репозитория; без них сборка падает с подсказкой. Ключ создаётся так: `keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000`. Версия — `WASTELAND_VERSION_CODE` и `WASTELAND_VERSION_NAME`.
- **Вход:** токены хранятся в `@capacitor/preferences` (в браузере — `localStorage`, общий интерфейс `TokenStore`). Ссылка из письма `https://<домен>/login?token=…` открывает приложение (App Links, хост берётся из `ANDROID_PUBLIC_URL`); сервер отдаёт `/.well-known/assetlinks.json` по `ANDROID_PACKAGE` и `ANDROID_CERT_FINGERPRINTS` (SHA-256 ключа подписи; при Play App Signing — ключа из консоли Play). Кнопка Telegram открывает бота в приложении Telegram. Сервер должен разрешать CORS для `https://localhost` — origin WebView.
- **Поведение:** альбомная ориентация, полноэкранный режим (панели появляются по свайпу), отступы под вырез камеры через `env(safe-area-inset-*)`. «Назад» в забеге — пауза, в убежище и на экране входа — выход с подтверждением. Сворачивание ставит забег на паузу и выключает звук (в браузере уход со вкладки тоже ставит паузу).
- Иконка и заставка генерируются `make assets` из спрайта героя.

## Проверка вручную

1. Запустите `make dev`, откройте клиент и войдите как гость, по почте или через Telegram. Откроется убежище: крышки, лучшее время, число забегов и список улучшений с ценами. Нажмите «Выйти из убежища» (или пробел). Герой двигается через WASD/стрелки, на таче — плавающим джойстиком слева. Оружие автоматически стреляет в ближайшего врага.
2. Соберите кристаллы опыта, выберите улучшение кликом или клавишами 1–3. Нажмите P для паузы. После смерти откроется итоговый экран: сначала оценка награды, затем награда от сервера и новый баланс. «В убежище» возвращает в хаб. Если сервер недоступен, появится «Повторить»; после запуска сервера повтор засчитает тот же забег.
3. В убежище купите улучшение (первый забег даёт около 10–15 крышек, «Бронепластины» стоят 30). Баланс уменьшится на цену, уровень и следующая цена обновятся. В следующем забеге «Полевая подготовка» увеличивает максимум здоровья на HUD. Чтобы проверить 409, в другой вкладке купите улучшение и затем нажмите «Купить» в старой: появится «Профиль изменился», профиль перечитается.
4. Прогресс на другом устройстве: в убежище гостя привяжите почту, откройте игру в другом браузере, войдите по коду из лога сервера — крышки и улучшения те же.
5. Поддельная сводка: возьмите `access_token` из `localStorage['wasteland.auth.v1']`, вызовите `POST /api/v1/runs/start`, затем сразу `POST /api/v1/runs/{run_id}/finish` с `{"content_hash": "...", "duration_seconds": 60, "kills_by_type": {"ghoul": 10000}, "wave_reached": 3, "boss_killed": true, "picked_caps": 10000}`: в ответе урезанная награда и флаги `duration_clamped`, `kills_clamped`, `caps_clamped` и т. д.
6. Откройте `/api/v1/health`: при доступной БД ответ `{"status":"ok","database":"ok"}`. Если БД недоступна, сервер вернёт HTTP 503 в формате `{ "code": ..., "message": ... }`.
7. Контент: на 4:30 появляется предупреждение и громила с полосой здоровья внизу; после убийства подберите сундук — откроется экран с улучшениями. Ящики на карте разбиваются касанием или выстрелом, из них падают аптечки, магниты, гранаты и крышки (над героем всплывает подпись). В 13:00 приходит Король свалки под отдельную музыку; при 66 % и 33 % здоровья он меняет тактику и зовёт подмогу, после убийства — «ПОБЕДА!» и бонус к награде. Для быстрой проверки в dev используйте `?wave=8` (13:00).
8. Графика и звук: в убежище играет музыка «Убежище», интерфейс зелёный, со сканлайнами. В забеге герой и враги анимированы и разворачиваются по направлению движения, у врагов есть анимация смерти, у попаданий — искры, кристаллы мерцают. Звучат выстрелы (у обреза свой звук), попадания, подбор опыта, новый уровень и урон. При смерти герой падает, через секунду открываются итоги со звуком награды. Снимите галочки «Музыка», «Звуки», «ЭЛТ-эффект» — каждая выключается сразу и сохраняется после перезагрузки.
9. Эволюция: прокачайте оружие до 8-го уровня и возьмите парный перк (см. таблицу выше) — на следующем повышении уровня первой будет золотая карточка «ЭВОЛЮЦИЯ»; после выбора иконка и поведение оружия меняются (у дрона — 7 дронов постоянно на орбите). Если в этот момент открыть сундук, эволюция придёт из него.
10. На экране убежища можно привязать почту/Telegram к гостю и удалить аккаунт вместе с данными. Гостю после третьего забега показывается предложение привязать вход. Выполните `make test` и `make content-check`.

В dev-режиме `?autostart` сразу начинает забег из убежища, `?seed=42` заменяет серверный seed, `?wave=1` запускает вторую волну (нумерация с нуля). Во второй волне появляются два типа врагов. На повышении уровня обрез появляется среди карточек как новое оружие. HUD показывает FPS, число врагов и снарядов. Контрольный замер в headless Chromium после перехода на анимированные спрайты (этап 5): 300 врагов и 500 снарядов, 120 кадров за 2 секунды.
