# Пустошь

Survivor-like про выжившего у убежища. Сейчас реализованы **этапы 0–1: каркас и играбельное ядро**. [Полный план](docs/PLAN.md).

## Требования

- Node.js 22.12+ и npm
- Python 3.12 и [uv](https://docs.astral.sh/uv/)
- PostgreSQL 16+ (локально, без Docker)

## Первый запуск

```bash
createdb wasteland
cp .env.example .env
make install
make migrate
make dev
```

Если PostgreSQL использует отдельного пользователя, измените `DATABASE_URL` в `.env`. URL должен начинаться с `postgresql+asyncpg://`. `make dev` запускает сервер на `http://localhost:8000` и клиент на `http://localhost:5173`. Для проверки сервера откройте `http://localhost:8000/api/v1/health`; игра доступна в браузере на порту 5173.

## Команды

| Команда | Назначение |
| --- | --- |
| `make install` | Установить зависимости клиента и сервера |
| `make dev` | Запустить оба dev-сервера |
| `make migrate` | Применить миграции Alembic |
| `make test` | Запустить проверки Python, тесты и проверки клиента |
| `make content-check` | Проверить JSON-файлы каталога контента |

Числа текущего забега лежат в `content/balance.json`. Полные схемы контента и проверка ссылок появятся на этапе 2. Аккаунты, мета-прогрессия и Android относятся к следующим этапам.

## Проверка вручную

1. Запустите `make dev`, откройте клиент и нажмите на экран. Герой двигается через WASD/стрелки, на таче — плавающим джойстиком слева. Оружие автоматически стреляет в ближайшего врага.
2. Соберите кристаллы опыта, выберите улучшение кликом или клавишами 1–3. Нажмите P для паузы. После смерти откроется итоговый экран, откуда можно начать снова.
3. Откройте `/api/v1/health`: при доступной БД ответ `{"status":"ok","database":"ok"}`. Если БД недоступна, сервер вернёт HTTP 503 в формате `{ "code": ..., "message": ... }`.
4. Выполните `make test` и `make content-check`.

В dev-режиме `?autostart` сразу начинает забег; HUD показывает FPS, число врагов и снарядов и seed. Контрольный замер в headless Chromium: 300 врагов и 500 снарядов, 120 кадров за 2 секунды.
